# 手机与 iPad 前端验收

日期：2026-11-06。环境：Windows、微信开发者工具 2.02.2608070、基础库 3.17.6。

## 修改内容

- 13 页的设计尺寸统一使用受限的 CSS 变量。保留手机比例；480px 以上字体、图标和间距停止等比放大。
- 主页面最大宽度 760px，二级表单最大宽度 600px；iPad 横竖屏居中。320px 小屏下小屋情绪卡、瞬间卡和等待卡改为单列。
- 修复资料页底部操作栏残留的 `translateX(-50%)`，消除左侧裁切；统一操作栏居中、安全区、底栏避让与页面底部滚动留白。
- 主要操作按钮、勾选按钮和输入框增加触控尺寸；输入区使用原生键盘避让；长昵称、标题和文本允许换行。
- 开启 `resizable` 和页面自动旋转，导航组件随窗口变化重新计算胶囊避让；二级页直接启动时，返回按钮回到对应主页面。
- 四项心愿全部可勾选并恢复状态，拒绝无效索引；缓存主页面返回时刷新资料、纪念日和心愿。
- 恢复草稿中的双图、悄悄话与隐私开关；双图排版切换实际更新照片布局；等待页显示提交的照片和文字，返回编辑复用已有页面。
- 修复历史双图预览入口；写信日期控件支持原生日期选择并显示实际所选日期；演示密令允许首尾空格和大小写差异。

## 验证方法

1. `npm run check`：13 路由、资源、TypeScript 检查。
2. `npm test`：18 项权限边界和本地流程测试。
3. `npm run check:native`：用户已安装的微信官方 WXML/WXSS 编译器检查 35 个文件。
4. `node scripts/check-responsive.cjs`：实际编译后的微信原生渲染层，通过 CDP 分别设置 320×568、375×667、390×844、430×932、768×1024、1024×768、1194×834，检查 13 页共 91 个页面/尺寸组合的 DOM 几何数据。结果在 `responsive-validation.json`。
5. 微信开发者工具实际切换 iPad 机型并旋转，核对排版与底栏；`--native` 导出当前机型各页面的原生截图与 `native-device-*-validation.json`。实际机型截图以 `artifacts/responsive/actual-` 开头。
6. `node scripts/check-runtime-flows.cjs`：在编译后的 AppService 运行心愿勾选、瞬间提交与返回、过期日期拦截、寄出记录和邀请确认五组链路。测试前快照本地业务缓存，结束后恢复。结果在 `responsive-flow-validation.json`。

## 验收边界

最终结果：91 组布局测量未发现普通内容横向溢出或固定操作栏越界；18 项测试通过；35 份原生模板/样式编译通过；5 组 AppService 链路通过。实际 iPad 机型遍历 13 页，小屋横竖屏均已目视核对；实际 320px 机型遍历至写信页，并单独核对瞬间页照片加载后的截图。恢复了用户原来的 iPhone 12/13 (Pro) 模拟器机型。

- CSS 视口模拟只用于布局测量。开发者工具嵌入式 WebView 放大时会出现合成截图拼接异常，因此不把此类截图作为视觉验收证据，视觉核对使用实际模拟器机型。
- 320px 实际机型连续 `reLaunch` 到等待页时，开发工具曾返回 `reLaunch:fail timeout`；重新切换 tab 即恢复。该轮实际机型遍历只记前 10 页；13 页完整覆盖来自 91 组布局测量和 iPad 遍历，不将该次超时记作通过。
- 最后一次 CDP 日志采样为 0 错误、1 条开发工具注入代码使用旧系统信息接口的警告，不宣称所有基础库/工具日志均无警告。
- 模拟器不能代替 iPhone、Android 和 iPad 真机。系统键盘、相册授权、多窗口与系统大字体仍需真机复核。
- 继续保持本地演示模式；没有部署云函数，也没有接入真实双人同步或投递。
